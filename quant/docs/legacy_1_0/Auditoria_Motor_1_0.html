HarpoonX · 29 octubre 2026 · versión 30.4.0

Un motor económico común para la cartera multi activo

Auditoría del código disponible, implementación y validación local. Prioridad: la red de pesca de acciones y la transición de un ranking técnico a decisiones medibles de beneficio neto y riesgo.

Resultado entregado. Núcleo Python funcional y puerta cuantitativa integrada en el coordinador para acciones, ETF, cripto y opciones. El núcleo también valora futuros mediante entradas normalizadas. Se ejecutaron 188 pruebas distintas: 188 aprobadas, cero fallos y cero omitidas.
Resultado financiero: todavía no determinado. No se entrenó un modelo observado ni se demostró beneficio incremental real. Los ejemplos y pruebas nuevos usan datos fabricados explícitos. No se enviaron órdenes externas ni se desplegó esta versión.

Arquitectura implementada

datos conocidos → variables → modelo congelado → escenarios conjuntos → valoración neta → asignación entera → controles del coordinador

Ocho variables: momentum de una, tres y doce barras; volatilidad de doce intervalos contiguos dentro de sesión; RVOL; desviación de VWAP; fuerza relativa contra SPY; spread relativo. El adaptador usa barras 5Min en valores y 15Min en cripto. Los modelos se ajustan por subyacente y deben conservar esas unidades.

La calibración exige al menos cien fechas distintas. Usa 60/20/20 cronológico, purga etiquetas que cruzan las fronteras y escoge entre tres lambdas Ridge en validación. El test compara MSE contra la media histórica del tramo anterior. Un bootstrap de bloques de cinco sesiones aplica ajuste de familia para activos y lambdas. Se guardan fechas, residuos fuera de muestra, hash de insumo y metadatos.

La asignación requiere veinte fechas comunes de residuos. Remuestrea los mismos índices para todos los activos, manteniendo dependencia transversal. La covarianza regularizada se utiliza para escalar estrés, no para inventar precisión de las colas. La función objetivo maximiza la esperanza neta menos una penalización aproximada de incertidumbre y otra de CVaR. Esa penalización de incertidumbre no constituye un intervalo de confianza formal.

SciPy/HiGHS resuelve cantidades enteras de lotes y activación de campañas. El conjunto de restricciones incluye efectivo, buying power, inventario, reservas, exposición bruta y por factor, cantidad máxima de posiciones, CVaR y tres escenarios de estrés. Efectivo sin invertir es una solución admisible. Las verificaciones posteriores al solver y el gate operativo preceden a una orden PAPER.

Lo que todavía separa el motor de una ventaja económica demostrada

  1. Panel observado verificable. Debe preservar universo por fecha, bajas, ajustes, timestamps de disponibilidad y BBO. En opciones se necesita una muestra de IV coherente con contrato y tenor; una serie genérica del ticker no basta para todas las opciones.
  2. Validación de beneficio, además de MSE. Congelar hipótesis y evaluar mejora incremental neta contra el mismo sistema sin el gate. Informar distribución por activo, costes, concentración, pérdidas máximas y sensibilidad. El holdout debe ser nuevo cuando se repita la búsqueda.
  3. Replay de ejecución y salidas. La valoración terminal actual no reproduce todas las rutas de TP, stop, trailing y fills parciales. No se puede presentar su esperanza como rentabilidad de la estrategia completa.
  4. Observación prospectiva. Ejecutar en sombra y PAPER con conciliación de fills reales del simulador, costes identificados y protección verificada antes de atribuir un resultado económico al cambio.
  5. Ciclo de vida y capacidad. Revisar dividendos discretos, eventos, ejercicio, vencimientos y ajustes de contratos; los futuros requieren margen y roll. El modelo no mide impacto de mercado ni garantiza protección frente a gaps, margin calls o precios fuera de los escenarios.

origin=OBSERVED es una declaración del productor de datos, no una firma del proveedor. execution_allowed expresa admisibilidad técnica; liveApproved=false y la ausencia de validación financiera independiente se conservan. No se entrega un artefacto observado aceptado ni se acredita una rentabilidad de dos dígitos, 20× o de campeonato.

Cómo usar la entrega

El paquete completo conserva el coordinador y añade quant/. El paquete del motor permite usar python -m harpoon_quant de forma independiente. Incluye ejemplo ejecutable de cinco clases, de origen sintético, y contrato detallado de insumos. Los comandos de instalación y pruebas están en README_ES.md; la integración y arranque en docs/QUANT_30_4_ES.md.

El ejemplo del coordinador activa el nuevo gate. Sin calibración observada admisible se bloquean nuevas entradas; las salidas siguen bajo supervisión. El archivo de modelo se indica mediante HARPOON_QUANT_MODEL y el intérprete mediante HARPOON_QUANT_PYTHON. Se conservan los controles originales de capital y riesgo del coordinador. El servicio independiente de opciones 1.2 no se fusionó con este paquete.

La revisión del repositorio conectado encontró un repositorio vacío; no se publicó código allí. El estado de despliegue no se verificó por falta de workspace seleccionado. Esta entrega es código y evidencia local, disponible para revisión y calibración.
