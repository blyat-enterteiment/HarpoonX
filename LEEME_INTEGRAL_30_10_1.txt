4. PRIMERA INSTALACIÓN CON DOCKER

Requisitos: Docker Engine con Compose v2 y Python >=3.11 en el host. La imagen instala
sus propias dependencias Node/Python. Configura los valores de .env.example en
un archivo .env privado o en el entorno del proceso:

  APCA_API_KEY_ID               clave PAPER de la cuenta dedicada
  APCA_API_SECRET_KEY           secreto correspondiente
  HARPOON_PANEL_PASSWORD        contraseña de al menos 32 caracteres
  HARPOON_DATA                  directorio persistente del host
  HARPOON_CONFIG                JSON original de configuración, fuera de DATA
  HARPOON_START_PAPER           1 para conservar el arranque automático previsto;
                               0 para iniciar con nuevas entradas pausadas
  BIND_HOST                    127.0.0.1 por defecto
  PORT                         10000 por defecto
  HARPOON_PUBLIC_ORIGIN         http://127.0.0.1:10000 para ese origen local

El archivo .env se interpreta como datos: no se ejecuta ni expande comandos.
No incluyas credenciales en el código o en los informes. La ruta de instalación
Docker pasa los secretos por entorno; Docker conserva sus metadatos habituales
de entorno. Los archivos de secretos del host no se montan automáticamente.

La configuración se monta como solo lectura y debe ser legible por UID1000 del
contenedor. El instalador no cambia sus permisos ni reescribe su contenido.
El directorio de datos se monta en /var/data y conserva el SQLite de la cuenta.
El Python cuantitativo del contenedor usa la venv prevista en Dockerfile.xxx,
independientemente del Python configurado en el host.

Desde el directorio descomprimido:

  bash install.sh --check
  bash install.sh --plan

Esas dos órdenes validan y muestran el plan local sin invocar Docker, consultar
la cuenta ni enviar órdenes. Un resultado local correcto no acredita permisos
del broker, contabilidad, calibración ni ventaja económica.

Cuando se ejecuta la instalación dentro de la autorización operacional vigente:

  bash install.sh
  bash status.sh

El primer comando construye y solicita el arranque de un único servicio
xxxultimate. El segundo informa contenedores y salud HTTP. La versión entregada
no fue desplegada ni arrancada contra una cuenta desde el entorno de evaluación.
El runtime realiza la vinculación de cuenta y las comprobaciones del journal.
Una instancia legacy activa bloquea un arranque simultáneo de la ruta nueva.

Panel local predeterminado: http://127.0.0.1:10000
Usuario: trader. Contraseña: HARPOON_PANEL_PASSWORD.
Para un origen externo se exige HTTPS; este paquete no crea automáticamente un
dominio ni un proxy TLS. render.yaml conserva la ruta de despliegue documentada.

5. ACTUALIZAR UNA INSTALACIÓN EXISTENTE

Conserva el mismo HARPOON_DATA, el SQLite y el JSON de configuración vinculados
a esa cuenta. No sustituyas límites o identidad por los del ejemplo. No borres
historiales para superar un bloqueo. La pausa persistida sobrevive al reinicio.

Conserva una copia recuperable del estado antes de sustituir una instalación.
La gestión de posiciones debe coordinarse con la interrupción del proceso: no
ejecutes dos motores sobre la misma cuenta para intentar evitar esa interrupción.
El comando stop.sh detiene el contenedor y advierte que interrumpe protección y
salidas por software. No envía cierres/cancelaciones ni elimina el journal.

  bash stop.sh

La compatibilidad legacy es explícita:

  bash status.sh --legacy
  bash stop.sh --legacy

Estos comandos se limitan al compose.json legacy existente. No implican migración
automática de posiciones, secretos o configuración entre las dos arquitecturas.
